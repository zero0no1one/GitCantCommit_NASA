# Exploration-era planning scenario data

These are **hypothetical 30-day UTC analysis windows**, not NASA launch or landing dates:
- 2027-11-15 to 2027-12-15: late-2027 VIPER delivery context.
- 2028-02-18 to 2028-03-19: early-2028 Artemis IV context.
- 2028-10-15 to 2028-11-14: late-2028 Artemis V context.

NASA schedule sources:
- https://www.nasa.gov/news-release/nasa-selects-blue-origin-to-deliver-viper-rover-to-moons-south-pole/
- https://www.nasa.gov/mission/artemis-iv/
- https://www.nasa.gov/event/artemis-v/

Six curated site IDs: apollo-11, apollo-17, sl3, site04, site07, site11. Apollo 11 and sl3 in the early-2028 window remain in the existing data/mission.json; the corresponding exploration pack stores only four new sites to avoid duplicating the already validated records.

Generated by tools/data/build_exploration.py using the existing build_site pipeline. Each new record has 10-minute topocentric JPL Horizons Sun and Earth samples, a 0.1-degree terrain skyline, full/any Sun intervals, Earth-center-up intervals, and +/-0.1-degree skyline timing sensitivity. The cross_checks object compares topocentric data with a separate Horizons subpoint table and local geometry.

**Validation status: provisional.** No new site-window record has passed full independent terrain or event validation. The +/-0.1-degree band is a sensitivity test, not a complete uncertainty budget. Apollo 17 currently uses only the coarse 7.6 km global LDEM_4, so its terrain-horizon and derived visibility results must not be presented as verified. Polar sites require local skyline cross-checks with PGDA, Quickmap, and Moon Trek. No pack establishes electrical power, a radio link, landing safety, or mission feasibility. The Godot game must not treat these packs as scored science until validation is complete.
